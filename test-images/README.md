图片放在 `test-images/`，用微信开发者工具「选择图片」直接选本地文件。

## 程序生成的测试图

用 `node scripts/gen-test-images.mjs` 重新生成。

| 文件 | 测什么 | 怎么看结果 |
| --- | --- | --- |
| `gen-pixel-16x16.png` | **直接导入模式** | 应该被自动识别为像素图，1:1 还原成 16×16，每格颜色和原图完全一致 |
| `gen-colorchart.png` | **色彩还原上限** | 221 个色号排成网格，转出来应该能一一对应回原色，用它判断色卡准不准 |
| `gen-geometry.png` | **边界与细线** | 黑白棋盘 + 四色块 + 20 条细线，细线全丢说明格数不够或去噪过猛 |
| `gen-gradient.png` | **渐变断层** | 天空和地面的渐变，色数少时会出现明显色阶，用来判断色数够不够 |
| `gen-transparent.png` | **透明通道** | 中间橙色圆，四周透明。应该只生成圆形部分的格子，四周是空格 |

## 建议的测试顺序

1. **先跑 `gen-pixel-16x16.png`**：验证直接导入这条链路是通的（最快能看出对不对）
2. **再跑 `gen-colorchart.png`**：验证色卡映射准确度
3. **然后 `lena.jpg`**：人像是最常见的需求，也是最难的
4. **最后 `baboon.jpg`**：毛发纹理是压力测试，糊了就说明格数不够

## 判断标准

看预览页左边的「算法输入」和右边的「成品」：

| 左边 | 右边 | 说明 |
| --- | --- | --- |
| 已经糊 | 糊 | 格数不够，加大格数 |
| 清楚 | 糊 | 配色或去噪有问题 |
| 清楚 | 有大量孤立小色块 | 点「去杂质」 |
| 清楚 | 清楚但颜色偏 | 色卡覆盖不足，是数据问题不是算法问题 |
